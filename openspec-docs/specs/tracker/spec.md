# specs/tracker/spec.md

## MUST
1. MUST хранить задачи с полями `id`, `title`, `hours`, `done`.
2. MUST при старте показать пример: Чтение 2ч done; Практика 4ч active; Повторение 2ч active (всего 8ч, выполнено 2ч, прогресс 25%).
3. MUST позволять добавлять, удалять и переключать `done` с реальным изменением данных и UI.
4. MUST отклонять название после `trim`, если оно пустое; MUST показывать ошибку рядом с формой; MUST сохранять введённые значения для исправления.
5. MUST принимать часы только как число в диапазоне 0.5–24 с шагом 0.5; пустое ≠ 0; отрицательные и невалидные значения отклоняются с видимой ошибкой.
6. MUST считать `progress = round(100 * sum(hours where done) / sum(hours all))`; если задач нет — 0%, без NaN/Infinity.
7. MUST применять фильтр только к видимому списку; итоговые часы и прогресс MUST считаться по всем задачам.
8. MUST работать в обычном браузере одним HTML-файлом без внешних ресурсов.

## Scenarios

### T1 исходный пример
- WHEN приложение открыто со стартовыми данными
- THEN видны 3 задачи; всего 8 часов; выполнено 2 часа; прогресс 25%

### T2 статус
- WHEN «Практика» отмечена готовой
- THEN выполнено 6 из 8 часов; прогресс 75%; данные и интерфейс согласованы

### T3 фильтр
- WHEN возвращены исходные задачи AND выбран фильтр «активные»
- THEN в списке только «Практика» и «Повторение»; общий прогресс остаётся 25%

### T4 ошибки ввода
- WHEN отправлено пустое название OR пробелы OR пустые/отрицательные часы OR часы вне 0.5–24 OR шаг не 0.5
- THEN задача не добавляется; видна ошибка; введённые значения сохраняются

### T5 пустое состояние
- WHEN все задачи удалены
- THEN 0 часов и 0%; нет NaN/Infinity; интерфейс продолжает работать (можно добавить новую задачу)
